# BUBBLE_LIFECYCLE

Document Level: Living

Version: 1.0

---

## Bubble Lifecycle

Bubble represents the present.

It is not a chat message.

It is not a history record.

It is NANA's current voice.

At any moment, there should only be one active Bubble.

The Bubble exists to make users feel that they are talking with NANA in the present, while previous conversations gradually become memories.

---

# Purpose

The Bubble is designed to represent NANA's current response.

It creates a natural transition between:

Memory

↓

Present

↓

Future

The Bubble always belongs to the present.

Once its lifecycle ends, it becomes part of Memory.

---

# Core Principles

## Principle 1

There is only one active Bubble.

The user should never see multiple NANA Bubbles simultaneously.

---

## Principle 2

The Bubble always represents NANA's latest response.

Older responses belong to Memory.

---

## Principle 3

The Bubble must remain visible until the user sends the next message.

Typing inside the input field does NOT end the Bubble's lifecycle.

This allows users to:

- read comfortably
- think
- copy names
- compare ideas
- quote concepts

The Bubble should remain stable during this entire process.

---

## Principle 4

A Bubble only becomes Memory after the user sends a new message.

Sending a new message marks the end of the current conversation moment.

Only then should the Bubble leave the stage.

---

## Principle 5

The Bubble should never compete with Memory.

Memory represents the past.

Bubble represents the present.

These two roles must remain independent.

---

---

# Lifecycle States

## Idle

No Bubble is visible.

The stage is waiting for NANA.

---

## Appearing

Bubble enters the stage gently.

The appearance should feel calm.

The Bubble should never pop aggressively.

---

## Typing

Text appears progressively.

Typing should feel natural.

The speed should be fast enough to avoid interrupting reading.

The goal is to create the feeling that NANA is speaking.

---

## Reading

Typing is complete.

The Bubble becomes completely stable.

No movement should distract the user.

The user is reading.

---

## User Thinking

The user may pause.

Nothing changes.

The Bubble remains exactly where it is.

---

## User Typing

The user begins typing.

The Bubble remains visible.

The Bubble does NOT move.

The Bubble does NOT fade.

The Bubble does NOT shrink.

Users may still need to reference or copy Bubble content.

---

## User Sends Message

This is the official end of the Bubble's lifecycle.

The previous conversation is now complete.

The Bubble begins leaving the stage.

---

## Floating

The Bubble moves upward.

Movement should feel:

light

gentle

natural

It should appear as if the conversation is being placed into memory.

---

## Stored

The Bubble disappears from the stage.

Its content is now part of Conversation Memory.

Only Memory stores previous conversations.

---

# Memory Relationship

Bubble is temporary.

Memory is permanent.

The Bubble should never skip directly into Memory.

The transition itself is part of the experience.

---

# Visual Philosophy

Bubble should feel alive.

Memory should feel quiet.

Bubble attracts attention.

Memory waits patiently.

Bubble speaks.

Memory remembers.

---

# Timing Philosophy

Do not define the experience using milliseconds.

Define it using human feeling.

Appearing

Calm.

Typing

Natural.

Reading

Stable.

Floating

Light.

Disappearing

Gentle.

Every animation should serve the conversation.

Never perform animation simply because animation is available.

---

# Forbidden Behaviors

The following behaviors are not allowed.

✗ Multiple active Bubbles.

✗ Bubble disappearing when the user starts typing.

✗ Bubble entering Memory before the user sends a message.

✗ Bubble and Memory displaying the same response simultaneously.

✗ Bubble covering the input field.

✗ Bubble stealing keyboard focus.

✗ Bubble animation distracting users from reading.

✗ Bubble becoming larger while typing.

✗ Bubble shaking, bouncing excessively, or behaving like a notification.

---

# Design Philosophy

The Bubble is not a UI component.

It is the visible form of the present moment.

When users read the Bubble, they are sharing the current moment with NANA.

When they send a reply, that moment quietly becomes a memory.

The transition should feel effortless.

The user should never consciously notice the lifecycle.

They should simply feel that the conversation flows naturally.

---

# Future Expansion

Future milestones may introduce:

• Bubble breathing animation

• Emotional expression

• Voice synchronization

• Eye-contact timing

• Bubble emotion styles

These enhancements must never change the lifecycle defined in this document.

They only enrich its presentation.

---

# Final Principle

Memory represents the past.

Bubble represents the present.

Input represents the future.

NANA exists at the center of all three.

Every interaction should reinforce this relationship.
