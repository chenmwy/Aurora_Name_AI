# PROJECT INDEX

> Welcome to the documentation system of the NameAI Universe.

This document is the official entry point for every contributor.

Before reading any design document, writing code, modifying prompts, or creating new features, begin here.

---

# Documentation Purpose

The documentation system preserves the knowledge, principles and standards of the NameAI Universe.

Its purpose is to ensure that every future decision follows the same philosophy, regardless of who develops the project.

Documentation evolves together with the project.

No important knowledge should exist only inside conversations.

# Directory Responsibilities

## PROJECT_INDEX.md

The entry point of the documentation system.

Explains where every document belongs.

---

## CURRENT_STATE.md

The only dynamic document.

Records:

- Current milestone
- Current priorities
- Active development
- Frozen ideas
- Immediate next tasks

---

## 00_UNIVERSE

Defines the highest principles of the NameAI Universe.

Examples:

- Universe Constitution
- Core Protocol
- Roadmap
- Design Principles

---

## 01_STANDARDS

Defines standards shared across the entire project.

Examples:

- Documentation Standard
- Companion Standard
- World Standard
- Prompt Standard
- UI Standard

---

## 02_COMPANIONS

Defines every companion living inside the Universe.

Each companion has independent documentation covering personality, memory, dialogue, skills and evolution.

---

## 03_WORLDS

Defines every companion's world.

Each world documents its visual identity, atmosphere, interaction style and storytelling.

---

## 04_MECHANICS

Defines every reusable interaction system.

Examples include:

- Pearl System
- Shell System
- Memory System
- Emotion System
- Collection System

---

## 05_PRODUCT

Defines the complete user-facing product.

Examples include:

- User Journey
- Business Model
- Feature Planning
- Monetization
- Version Planning

---

## 06_ENGINEERING

Defines technical implementation.

Examples include:

- Project Structure
- Development Workflow
- Cursor Protocol
- Git Workflow
- API Design
- Database Design

---

## 99_ARCHIVE

Stores historical documentation.

Archived documents are preserved for reference but are no longer considered active specifications.

# Reading Order

New contributors should always follow this order.

```
PROJECT_INDEX

↓

DOCUMENTATION_STANDARD

↓

00_UNIVERSE

↓

01_STANDARDS

↓

Relevant Documents

↓

CURRENT_STATE
```

Read philosophy before implementation.

Never reverse this order.

---

# Documentation Rules

Every document must:

- Follow the Documentation Standard.
- Have exactly one responsibility.
- Use the official Header.
- Belong to the correct directory.
- Be updated together with development.

When uncertainty exists,

documentation has higher priority than assumptions.
